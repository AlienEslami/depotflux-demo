# Synthetic OT protocol and test plan

## Purpose and constraints

This plan verifies the software-only boundary between DepotFlux and its
synthetic site controller. It must run on loopback or the isolated Docker lab.
It must never be pointed at a routable PLC, charger, building controller, field
gateway or production network. Test data is synthetic. `direct_asset_control`
remains `false` because no physical adapter exists.

## Protocol profile

- Transport: TCP, lab port 1502; the standard Modbus port is intentionally not
  host-published.
- Unit identifier: 1.
- Reads: function 03 (read holding registers).
- Writes: function 16/0x10 (write multiple registers), one atomic block starting
  at register 100 with quantity 3.
- Values: import magnitude, export magnitude and explicit command mode. Power
  scale is 0.1 kW/count.
- Readback: one snapshot from 100 through 130 returns setpoint, software
  measurement, controller state, alarm bits and heartbeat.
- Response validation: transaction/unit/function/address/count must match.
- Exceptions: illegal function `0x01`, illegal address `0x02`, illegal value
  `0x03`, gateway-target failure `0x0B`.
- Client timeout defaults to 1 second with two retries (three total attempts).
  Code prevents more than three retries.

This is a project-specific Modbus profile. No vendor interoperability or
conformance claim is made.

## Deterministic scenario matrix

| ID | Scenario/input | Expected prevention or response | Evidence/detection |
|---|---|---|---|
| OT-S01 | Successful run, matching approval hash, valid interval/key | FC10 accepted; FC03 readback matches derived setpoint | `approved_dispatch_applied`, request/response hex, controller snapshot |
| OT-S02 | Wrong or missing control key | HTTP 401; no Modbus frame | `invalid_credential`, high severity |
| OT-S03 | No approval or immutable rejection | HTTP 409; no Modbus frame | `immutable_operator_approval` |
| OT-S04 | Result digest altered after approval | HTTP 409; no Modbus frame | `approval_result_hash` |
| OT-S05 | Reuse accepted command UUID | Gateway HTTP 409; no second write | `replayed_command` |
| OT-S06 | Issued two minutes ago, expired | Gateway HTTP 409 | `stale_command` |
| OT-S07 | Derived power above modeled site capacity | API HTTP 409 before gateway | `site_capacity_envelope` |
| OT-S08 | Non-gateway peer accesses PLC | Modbus exception; alarm bit | PLC JSON `direct_plc_access_rejected` |
| OT-S09 | Broad read of undefined registers | Modbus exception; alarm bit | PLC JSON `register_scan_rejected` |
| OT-S10 | Controller socket absent | Bounded retry, explicit 503, best-effort zero-power action | `controller_exchange_failed` |
| OT-S11 | Heartbeat remains unchanged | Status fails; explicit safe-state write is attempted | `controller_heartbeat_lost`; state becomes safe |
| OT-S12 | Correct separate emergency key and reason | Zero setpoint with mode 1, state 3, safe alarm | `emergency_safe_state_activated` |
| OT-S13 | Ordinary approved zero setpoint | Mode 0, controller remains active | Codec/controller regression test |
| OT-S14 | API/worker/monitor resolve PLC name | Resolution must fail | `network-isolation.json` |

All database-backed outcomes include actor, issued/completed/created timestamps,
command UUID, correlation UUID, reason code/message and result digest where a run
exists. Accepted attempts additionally include both frames and the controller
response. Rejected attempts prove that no frame was generated by storing null
frame fields.

## Commands

Start the lab with generated local secrets:

```powershell
./scripts/start_ot_lab.ps1
```

Run focused tests, Compose smoke scenarios, network checks, and capture evidence:

```powershell
./scripts/run_ot_evidence.ps1
```

Run the complete regression suite and dashboard checks:

```powershell
python -m pytest -q
Push-Location dashboard
npm run lint
npx tsc --noEmit
npm run build
Pop-Location
```

Run a clean migration rehearsal against a disposable database or the empty named
Compose volume and review the upgrade sequence through revision 0007:

```powershell
docker compose --env-file .demo/ot-lab.env logs api
```

## Evidence acceptance criteria

- Every expected status and reason code matches the matrix.
- Accepted dispatch has non-empty request and response frames and matching
  controller measurement.
- Rejected API-policy scenarios have no frame.
- Accepted and rejected database rows have a security event with the same
  correlation ID.
- Only the gateway resolves/connects to `plc-simulator`.
- PostgreSQL applies migrations 0001 through 0007 without auto-create fallback.
- All containers report healthy and PLC/gateway publish no host ports.
- Tests are repeatable; variable IDs/timestamps are evidence metadata, not
  expected-value inputs.

## Known test limitations

The lab does not measure deterministic real-time deadlines, packet loss under
load, multi-replica replay behavior, TLS/mTLS, certificate rotation, firewall
rules, intrusion-prevention efficacy, SIEM rule execution, high availability,
database point-in-time recovery, hardware behavior, electrical protection, or
functional safety. Docker Desktop networking can differ from a Linux production
host. These gaps must remain visible in any demonstration or interview claim.
